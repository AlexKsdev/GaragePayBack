## 📋 **Core Development Principles**

### ✅ **DRY (Don't Repeat Yourself) — Reusable Code**

**Where to reuse code:**
- **PrismaService** — Database connection wrapper (already in `src/database/prisma.service.ts`)
- **DTOs + Validators** — Define once, import everywhere (`@IsEmail()`, `@IsNotEmpty()`)
- **Guards & Strategies** — Auth patterns in `src/modules/auth/guards/` and `src/modules/auth/strategies/`
- **Common Decorators** — `@CurrentUser()`, `@Roles()` in `src/common/decorators/`
- **Interceptors** — Logging, transform response in `src/common/interceptors/`
- **Error Handling** — HTTP exceptions filter in `src/common/filters/`

**Example DRY pattern:**
```typescript
// ❌ DON'T: Validate email in every service
if (!email.includes('@')) throw new BadRequestException('Invalid email');

// ✅ DO: Use DTO validators once
export class CreateUserDto {
  @IsEmail()
  email: string;
}
```

---

### ⚠️ **Avoid Overcoding — Keep It Simple**

**DO NOT:**
- ❌ Write 500-line service files — split into smaller methods
- ❌ Duplicate DTO validation across services — define once in DTO
- ❌ Hardcode magic strings — use constants
- ❌ Test trivial getters/setters — focus on business logic
- ❌ Ignore Prisma relations — use `.include()` and `.select()` efficiently

**DO:**
- ✅ Service methods 20-50 lines max
- ✅ One responsibility per method (Single Responsibility Principle)
- ✅ Reuse validation decorators
- ✅ Use Prisma for complex queries
- ✅ Test only meaningful logic

---

### 📦 **Folder Structure — Strict Adherence**

Follow the structure in `structure.txt` WITHOUT deviation:
- **Modules:** `src/modules/[feature]/` (auth, users, garage, vehicles, payments, storage, ai, websockets)
- **Common Utilities:** `src/common/` (decorators, guards, filters, interceptors, middleware, pipes)
- **Configuration:** `src/config/` (database, auth, aws, openai)
- **Database:** `src/database/prisma.service.ts`
- **Tests:** `src/test/` or alongside components (`.spec.ts`)

**File naming:**
- `*.module.ts` — NestJS module
- `*.service.ts` — Business logic
- `*.controller.ts` — HTTP routes
- `*.dto.ts` — Data Transfer Objects
- `*.spec.ts` — Unit tests
- `*.gateway.ts` — WebSocket events
- `*.strategy.ts` — Passport strategies
- `*.guard.ts` — Authentication/Authorization guards
- `*.decorator.ts` — Custom decorators
- `*.interceptor.ts` — Request/response interceptors
- `*.filter.ts` — Exception filters
- `*.pipe.ts` — Validation pipes

---

## 🧪 **TDD — Unit Tests FIRST (Minimum)**

**Write tests BEFORE implementation for:**
- Service methods (business logic)
- Guards (JWT, roles validation)
- Strategies (JWT, local auth)
- Decorators (custom logic)
- Pipes (validation)

**DO NOT write tests for:**
- Simple CRUD getters (auto-tested via integration)
- HTTP route mapping (NestJS handles it)
- Configuration files


### **Run Tests in Watch Mode (TDD)**

```bash
npm run test:watch
```

```typescript
import { Injectable } from '@nestjs/common';
import { AuthGuard } from '@nestjs/passport';

@Injectable()
export class JwtGuard extends AuthGuard('jwt') {}
```

**Usage in Controller:**

### **3. DTO Validation Pattern**

**Location:** `src/modules/[feature]/dto/create-*.dto.ts`

```typescript
import { IsEmail, IsNotEmpty, MinLength } from 'class-validator';

export class CreateUserDto {
  @IsEmail()
  email: string;

  @IsNotEmpty()
  @MinLength(6)
  password: string;

  @IsNotEmpty()
  name: string;
}
```

**Module registration:**
```typescript
import { ValidationPipe } from '@nestjs/common';
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.useGlobalPipes(new ValidationPipe());
  await app.listen(3000);
}
bootstrap();
```

### **4. Service-to-Controller Data Flow**

**Service (Business Logic):**
```typescript
async createUser(dto: CreateUserDto): Promise<UserResponseDto> {
  const hashedPassword = await bcrypt.hash(dto.password, 10);
  const user = await this.prisma.user.create({
    data: { ...dto, password: hashedPassword },
    select: { id: true, email: true, name: true }, // Don't expose password
  });
  return user;
}
```

**Controller (Routes):**
```typescript
@Post()
async create(@Body() dto: CreateUserDto): Promise<UserResponseDto> {
  return this.usersService.createUser(dto);
}
```

### **5. Pagination DTO Pattern**

**Location:** `src/common/dto/pagination.dto.ts`

```typescript
import { IsOptional, IsPositive } from 'class-validator';
import { Type } from 'class-transformer';

export class PaginationDto {
  @IsOptional()
  @Type(() => Number)
  @IsPositive()
  page: number = 1;

  @IsOptional()
  @Type(() => Number)
  @IsPositive()
  limit: number = 10;
}
```

**Usage in Service:**
```typescript
async findAll(pagination: PaginationDto) {
  const skip = (pagination.page - 1) * pagination.limit;
  return this.prisma.user.findMany({
    skip,
    take: pagination.limit,
  });
}
```

## ⚠️ **Common Mistakes to Avoid**

| ❌ Mistake | ✅ Solution |
|-----------|-----------|
| Business logic in Controller | Move to Service, keep Controller thin |
| Forget ValidationPipe in main.ts | Enable globally: `app.useGlobalPipes(new ValidationPipe())` |
| Duplicate DTOs | Define once, import everywhere |
| Password in response | Use `.select()` to exclude sensitive fields |
| No unit tests | Write tests BEFORE implementation |
| Overcomplicated Service methods | Keep methods ≤ 50 lines, use helpers |
| Hardcoded strings | Use config/constants files |
| N+1 query problem | Use Prisma `.include()` or `.select()` |
| Missing error handling | Use HttpException, create error filter |
| Test the framework (not code) | Test YOUR business logic only |
